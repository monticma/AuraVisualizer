## [Unreleased]

### Added
- **`global-use` edges — the runtime half of a script-tag architecture (V4-09)** — files loaded as plain `<script>` (no `import`, no module system) expose a namespace and consume each other through it: `sprites.js` defines `window.AuraSprites`, `app.js` calls `AuraSprites.ripple(…)`. Those couplings were invisible, so the satellites showed `fan_in = 0` with an empty blast radius — renaming one function in `sprites.js` broke the whole panel without a single warning. Aura now pairs namespace definitions (`window.X` / `globalThis.X` / `self.X`) with their reads — plain `X.member` and the guarded `window.X.member` form — and emits a cyan **`global-use`** edge at confidence **0.6**. Both sides come from the Tree-sitter AST, so comments and string literals never produce an edge, a file is never linked to itself, and the `script` edge keeps its own meaning (“loaded by” vs “used by”). On this repository it surfaces **27 edges** (`app.js` → 15 satellites, plus `risk ↔ views ↔ timeline`, `warps → flight`, `query-ui → query`…), which makes fan-in, blast radius and cycles honest for script architectures. The index survives incremental saves (a changed file drops the names it owned and re-registers the new ones; a cache hit rebuilds it from the stored edges), and the **Edge confidence** slider hides the edges above 0.6. `PARSER_VERSION` is bumped to `2026-11-04.1`: a relation-set change must force a full re-analysis, otherwise an existing database keeps the relations of an older parser forever (an incremental run only re-parses files that changed — that is how a cache ended up with zero `script` edges). A regression test rebuilds a provider file through `rebuildSingleFile` and asserts the `script` / `stylesheet` relations are still emitted. 16 unit tests cover the extractors, the graph wiring, the incremental update and the cache restore.
- **Session tools + server instructions for agents (V3-16)** — the MCP surface (and `@aura`, which shares the registry) gains the four tools an assistant needs to *work* in a repository instead of only querying it. **`build`** answers “can I trust this graph?”: analysis timestamp and age, file/link counts, the commit analysed (from the persisted fingerprint) vs the live `HEAD`, a `stale` flag (`null` when undecidable — no analysis, no fingerprint or no git) and a written reason. **`explain_file`** returns one aggregated briefing for a file — metrics, risk score with reasons, cycles, dead/unused symbols, incoming/outgoing `call_sites`, dependencies/dependents, heritage, co-change partners, architectural community — instead of a chain of five calls. **`hotspots_in_changes`** ranks the changed files by risk, working tree by default (`git diff --numstat HEAD` + `git status`, untracked included) or a branch vs its merge base when `base` is given, each row carrying `+/-` and its risk reasons. **`list_repositories`** declares the served root, database path, analysis age, `HEAD`, staleness and every `git worktree` with its branch. The server also now sends an **`instructions`** block on `initialize`, telling the agent to call `build` first, prefer the indexed tools over shell `git`/`grep`, quote the `file:line` anchors and report staleness rather than presenting outdated metrics. The git-backed tools run through a new async dispatcher while the 18 deterministic ones keep their existing path; staleness rules, worktree parsing and the diff × risk merge live in a pure `ai/tool-core` module (16 tests) and a git reader with graceful degradation (13 tests, including a real temporary repository).
- **`path:line` anchors in every MCP tool (V3-15)** — whenever a tool knows a line, the entry now carries `file`, `line` **and** a ready-to-cite `anchor` (`"src/risk/risk-core.ts:142"`), so an assistant never has to concatenate anything: `search_symbols`, `search_docs`, `find_dead_code` (the `symbols.line` column was there but the payload dropped it), `find_unused_functions`, `find_heritage` (the line of the named class/interface is resolved from the symbol table) and `resolve_context`. `find_dependencies` / `find_dependents` also expose the direct **`call_sites`** (`from`, `to`, `line`, `anchor`) behind each edge, taken from the `function_calls` table. The formatting lives in a pure `ai/anchors` module (never `file:0` / `file:undefined`), and a **contract test** walks the tool payloads on a fixture database: a known line always yields both `line` and `anchor`, an unknown one yields neither (16 new tests).
- **Shallow-clone warning (V3-14)** — a `--depth 1` checkout (`actions/checkout` default in CI) makes `git log` return a single commit, so churn, co-change pairs and complexity trends are silently wrong. Aura now probes `git rev-parse --is-shallow-repository` (with a `.git/shallow` fallback for git < 2.15) plus `git rev-list --count HEAD` once per analysis, stores `{ shallow, commits }` on the graph meta (so it survives the instant-startup cache) and shows a **⚠️ banner** at the top of the Time Travel tab and a caption under **Codebase Health** in the Risk tab, both with `git fetch --unshallow` and a **Copy** button. Nothing is fetched automatically, the banner is dismissible for the session, and a complete history (or no repository at all) never triggers it — the wording and the decision live in a pure `git/shallow-core` module (12 tests).
- **Configurable focus distance** — `auraVisualizer.focusDistance` (40–400 scene units, default **120**, also a slider in ⚙️ Settings) sets how far from a node the camera parks when you focus it: a click, a search jump, a CodeLens focus, a breadcrumb restore or the 👁 follow editor. Lower for a tight close-up, higher to keep the neighbourhood in view. The value is clamped on both sides (host and webview), so a hand-edited setting can never park the camera inside the graph or light-years away from it. Edge clicks keep their own computed framing, and warps / view links replay their stored pose.
- **Navigation trail (V3-12)** — a thin strip over the graph records every place you visit (file click, search hit, CodeLens focus, pin, blast radius, applied query, warp, shared view). **Off by default**: turn it on with `auraVisualizer.breadcrumbs` (or the ⚙️ Settings checkbox), and switching it off clears and hides the trail. Each chip restores the **selection, pin/blast mode, query, tab and camera pose** of that place and drops everything after it; `⟵`, **Backspace** or `Alt+←` steps back one place. Consecutive duplicates are collapsed, the trail keeps the last 20 places, and the strip stays hidden until there is somewhere to go back to. Restoring a file place **re-centres the camera on it** exactly like a click (node entries carry no camera pose, so a stale one can never fight the focus flight; a warp entry stores the warp's own pose, and a pair is re-framed). Entries hold **ids and numbers only** — never live node or Three.js objects — so a re-analysis can never leave a dead reference behind (the cap, the duplicate filter, back/truncate and the chip labels live in a pure `navigation/breadcrumb-core` module, 22 tests). `Esc` records a **Reset** place, so even a full reset is reversible.
- **Click an edge to frame both endpoints (V3-11)** — edges are 1–2 px wide, so the link raycast tolerance is widened for picking; clicking one keeps the current viewing direction, flies the camera back just far enough for both nodes to fit the frustum (bounding sphere + FOV, 20 % padding, cold-start safe), draws a **pink glow** along the edge (bright core + wide halo, additive blending — glows on any GPU, no bloom pass needed) that follows the link exactly — the actual Bézier tube in curved mode, not a straight chord — and moves with both nodes frame by frame, and **multi-selects both endpoints** so the detail panel shows the aggregate stats of the pair. `auraVisualizer.edgeClickSelect` (on by default, also a checkbox in ⚙️ Settings) keeps the framing and the glow but drops the selection. Framing a single node keeps the familiar 120-unit close-up; the glow is disposed on the next click and on every dataset rebuild.
- **Agent context files (V3-10)** — **Aura: Generate Agent Context** writes the risk knowledge an AI assistant never has when it opens an unfamiliar repository: `.aura/hotspots.json` (the exact `get_hotspots` payload), `.aura/HOTSPOTS.md` (readable table, `.aura/` is git-ignored) and a short block between `<!-- aura:begin -->` and `<!-- aura:end -->` in the first instruction file that exists — `AGENTS.md`, `.github/copilot-instructions.md`, then `CLAUDE.md`. The block lists the top 10 hotspots with their reasons plus the repository health line (cycles, dead exports, architecture violations) and is **idempotent**: regenerating replaces only what sits between the markers, so the prose around it is never touched, a half-broken block is repaired instead of duplicated, and CRLF files keep their line endings. Only paths and metrics are written — never source code. If no instruction file exists the command offers to create `AGENTS.md`; `auraVisualizer.agentContext` (off by default) refreshes everything silently after each analysis and only ever updates a file that already exists. The generators live in a pure, `vscode`-free `agent-context` module (31 tests).

### Fixed
- **The symbol-search ripple was invisible** — the landing ring existed for exactly one frame: it was attached to `node.__threeObj`, and 3d-force-graph clears and rebuilds every node object whenever `nodeThreeObject` changes — which is precisely what selecting the symbol does. Measured in a real browser: the sprite was detached after a single `onBeforeRender` call. The ring now lives in the scene (like the edge glow), re-reads its node position every frame so it survives any rebuild, waits for the 800 ms camera flight to land (`delayMs`) instead of playing off-screen, and lasts 1.2 s instead of 700 ms. It removes itself and disposes its material at the end, and is dropped on every dataset re-feed or reset. The jsdom harness now asserts the real behaviour (scene attachment, node position, additive material, delay → growth → cleanup, disposal on re-feed) instead of only checking that the factory exists.
- **A satellite failure can no longer blank the panel** — the webview boot is now guarded: if any module throws while wiring its controls, the error is logged and startup continues, so `ready` is always posted and the host still sends the graph. Previously such a throw aborted `init()` silently and the 3D view stayed empty at startup.

## [1.5.1] - 2026-11-02

### Added
- **Global symbol search (V3-09)** — **Aura: Find Symbol…** (Command Palette) opens a QuickPick over `GraphDB.searchSymbols`: **kind chips** as the first rows (`function (82)`, `method (140)`, …), live filtering as you type, ↑↓ navigation, and a selection that reveals the file, flies to it, **explodes** it and selects the exact `file::symbol` node — marked with a one-shot **ripple** so the chosen function is unmistakable among the exploded satellites. The panel's search box now returns **symbols** after the file rows (⚡ `path:line`, click = same jump), and the ripple is limited to search jumps so ordinary clicks stay quiet. `GraphDB.searchSymbols` gained a limit parameter and a new `symbolKindCounts()` feeds the chips. 12 unit tests cover the list building, relevance order, dedupe, caps and chips.
- **Transitive imports (V3-08)** — the detail panel gains **🔗 Transitive imports** and **📥 Transitive dependents** sections: expand one to compute the closure on demand — `Imports 42 files · depth 4`, the **deepest chain** (`a.ts → b.ts → d.ts`) and one row per file with its depth badge (direct files in bold, click to select). The BFS lives in a pure `analysis/transitive` module (cycle-safe, deterministic, depth **and** node caps, 13 tests) and is computed in the extension host from the in-memory graph; `auraVisualizer.transitiveDepth` (1–10, default 5) sets the hop limit. The same closure enriches `find_dependencies` / `find_dependents` (MCP and `@aura`) with `max_depth`, `by_depth`, `longest_chain` and `truncated`, backed by a new `GraphDB.getEdges()`.
- **Branch review (V3-07)** — **Aura: Review Current Branch** (Command Palette, or the compare icon in the Source Control title bar) asks git what the branch changed: `git diff main...HEAD` with `--find-renames` and `--numstat` (never a shell), relative to the merge-base. A strip over the 3D graph shows `main...HEAD · 12 files · +340 −120 · Δcomplex +18`; **💥 Blast** seeds a multi-source impact cascade from every touched file and **⇄ Compare** pre-fills the existing Time Travel dual slider with the merge-base and HEAD — no duplicate visual mode. Renamed files are one entry, `+/−` lines come from git, and the complexity delta only appears when the history scan covers the branch. `auraVisualizer.reviewBase` picks another base (default: `main`, then `master`). 21 unit tests cover the NUL-separated parsers, rename handling, totals and the payload mapping.
- **Shareable view links (V3-06)** — **🔗 Link** in the toolbar (and `Aura: Copy View Link` in the Command Palette) copies a `vscode://monticma-aura.aura-visualizer-3D/open?state=…` URI that reopens the exact view: active tab, every filter (languages, palettes, heatmap, edge confidence, co-change, sizes), the camera pose — file-anchored like a warp, so it survives a rebuilt layout — and the query bar expression with its mode. The panel answers the link through `registerUriHandler` and applies it after the `graphRendered` handshake. Everything is validated on arrival: versioned payload, 8 KB cap, whitelisted keys, clamped numbers and finite camera coordinates, so a corrupted or hand-edited link only produces a message. A link captured in another workspace names that folder in a warning. 21 unit tests cover encoding, decoding, clamping and rejection.
- **Status bar finalisation (V3-05)** — every Aura badge is now switchable and addressable. A single setting, **`auraVisualizer.statusBar`** (default `true`), shows or hides the three items at once (file/link counter, active-file risk + hotspot alert, architecture violations) and applies on the spot — no reload, no re-scan. The items carry stable ids and names (`auraVisualizer.files` / `.risk` / `.arch`), so each one can be hidden from the status bar context menu and recognised by other extensions. The two click commands are now contributed: **Aura: Show Risk Map** and **Aura: Show Architecture**. Their logic moved to a pure `risk/statusbar-core` module (path mapping, hotspot selection, badge and tooltip wording — 18 tests) instead of living in the `vscode`-dependent entry point.
- **Import hover (V3-04)** — hover an import specifier (`from './x'`, `require('x')`, `import('x')`, Python `import`/`from … import`, `#include`, Java/Kotlin `import a.b.C`, Go `import "x"`, Rust `use`/`mod`, C# `using`, Ruby/PHP `require`, Lua `require("x")`, Bash `source`) and Aura shows the target file's card right in the editor: language, LOC, cyclomatic/cognitive complexity, fan-out/fan-in, architecture layer with its violation count, and the risk bucket — plus **⟡ Focus in Aura**, **💥 Blast radius** and **📂 Open file** command links. Specifiers are resolved with the same confidence ladder as the graph edges (relative → exact → extension → path suffix → basename); an ambiguous or unknown specifier shows nothing, and arbitrary text never produces a hover. Metrics come from the in-memory graph and risk snapshot (no SQLite query), parsed lines are cached per document version and per dataset, and `auraVisualizer.hover` (or the ⚙️ Settings checkbox) turns it off. 15 unit tests cover token extraction, resolution and the card layout.
- **Enriched command palette (V3-03)** — three navigation gestures now work from anywhere in VS Code. **Aura: Focus File in Graph…** opens a fuzzy picker over the analyzed files (path, language, directory, LOC, fan-in/out, architecture layer, violations; code only, documentation excluded, capped at 5 000 entries with a status-bar hint when truncated) and focuses the picked node with its detail panel. **Aura: Apply Saved Query…** replays a query saved from the query bar with its stored filter/highlight/select mode, most recent first, and says so explicitly when nothing is saved yet. **Aura: Add Warp Here** opens the existing warp naming modal on the live camera pose (`captureWarp`, queued behind the `graphRendered` handshake like the other graph actions) instead of requiring the Warps panel. The list building lives in a pure `palette-core` module (9 tests).
- **Blast radius from the code (V3-02)** — the impact analysis is no longer reachable only from inside the graph: right-click one or several files in **Source Control**, use the radio-tower button in the **editor title**, the **editor** right-click menu, or the **Explorer** context menu. A single file runs the usual blast (camera + depth colors); a multi-selection runs the **multi-seed impact cascade** (`startMultiNodeBlast`, already used by Time Travel) with every selected file at depth 0. Targets are resolved by a new pure helper (`src/commands/blast-targets.ts`, 13 tests): URIs are normalized to workspace-relative POSIX ids, deduplicated, capped at 50, and filtered to the analyzed graph — files outside the workspace or unknown to the graph are skipped, and the panel is not opened when nothing matches (the command falls back to the active editor when invoked from the palette without an argument). `sendBlastRadius` now carries `nodeIds[]` and still honours the single-node payload, queued behind the `graphRendered` handshake like the other graph actions.
- **Symbol CodeLens ⟡ (V3-01)** — every function, method, class, interface, struct, enum and type alias of an **analyzed** file now carries a `⟡ focus · flow · impact` CodeLens. Clicking it opens a quick pick with **Focus in Aura** (reveals the panel and centers the graph on the file), **Show flowchart** (the same AST flowchart as the graph detail panel, requested through the existing `flowData` round-trip) and **Blast radius**. Symbols and 1-based lines come from the graph database (`getNodeDetail`), so the lenses need no language server; a file that was never analyzed shows no lens, and an analyzed file without symbol rows falls back to the editor's document symbols. The three actions are also standalone commands (`focusSymbol`, `showSymbolFlow`, `blastSymbol`), a file caps at 300 lenses, and `auraVisualizer.codeLens` turns the feature off. The pure selection/placement rules live in `codelens-core` and are unit-tested (12 tests).

### Changed
- **Compact top bar, counted language buttons** — the per-language breakdown (`42 ts, 12 py, 8 css…`) no longer eats the top bar: it lives inside the language buttons of the filter bar, as a `filter-count` badge identical to the 📝 Notes one (`TS 42`). The top bar now only shows the two totals — files and links. **🌀 Warps** moved from the bottom filter bar to the top bar, right of **🗺️ Map**: it is a panel toggle like Map, not a graph filter, so it belongs with the other toolbar controls.
- **Toolbar polish** — **📤 Export** moved next to **🗺️ Map** (between 👁 Follow editor and Map) and the 👁 button lost its oversized 36 × 36 icon variant, so every right-hand control now shares the same height as the 📷 PNG button.
- Rules and baseline are side files: saving either re-evaluates immediately (`auraVisualizer.reloadArchRules`) without re-parsing the project or rewriting the DB. A syntax error leaves the rest of Aura working and is surfaced in the Architecture tab.

### Fixed
- **Transitive sections went blank after a click** — selecting a file from the Transitive imports / Transitive dependents list resets the lists for the new file, but a `toggle` event only fires when a `<details>` changes state: the section stayed open and empty until it was closed and reopened. An open section now re-asks for the new node by itself, so the closure reloads as soon as a row is clicked.
- **Clicking a filtered-out file made the graph disappear** — a documentation node (or any file whose language button is off) is not in the rendered dataset, so it has no force position: focusing it wrote `NaN` into the camera and the scene never painted again. Clicking such a file now turns its language filter back on (the 📄 Docs button lights up) and defers the camera move until the node has real coordinates; a node that stays out of the dataset is never focused, so the camera can no longer be poisoned.
- **Documentation nodes rendered almost black** — in the **Architecture layers** and **Communities** heatmaps a doc file had no value to colour with and was painted `#ffffff12` (7 % white), which reads as a black sphere on the dark background. Doc nodes now keep their language colour — the exact grey of the **📄 Docs** filter dot — and only dim like any other node when the view is pinned, blasted or narrowed by a query.
- **Blank PNG export from another tab** — 📷 grabbed the WebGL canvas at the size of a `display:none` container, so exporting while the Risk, Architecture, Matrix, Table… tab was active produced a 2 × 2 px image. The button is now hidden outside the **3D Graph** tab, the capture answers with an explicit error instead of an empty file (covers `Aura: Export Graph as PNG` in the Command Palette, which now warns before opening its dialogs), and the tooltip says so.
- **Deleted files counted as hotspots** — a file removed in the working tree can no longer contribute to `⚠ N hotspots in your changes`: it is gone, so it is not at risk any more. Hotspots are also deduplicated and sorted deterministically (risk descending, then path), so the badge count and the tooltip list always agree.
- **Import hover resolving package specifiers** — hovering `@scope/pkg/types.js` (or anything carrying an extension or a path) could land on an unrelated workspace file that merely shares its basename — `@modelcontextprotocol/sdk/types.js` pointed at `src/analyzer/types.ts`. The unique-basename fallback now only applies to a bare, single-segment, extension-less specifier (the `import helper` case that genuinely needs it); package specifiers show **no** card instead of a wrong one.
- **Cold start: a panel that never painted** — the webview now reports what it actually built: `graphRendered` carries the node count, panel size, canvas size, active tab and pause state, and an incomplete render posts **`renderFailed`** instead. The host then keeps its focus / blast / warp queue instead of acting on a dead panel — that was the grey screen with the warp naming modal on top — shows a one-time warning pointing at the Extension Host log, and the webview retries `initGraph` for a few frames when the panel has not been laid out yet (the actual cold-start cause). The loading overlay stays visible with an explicit message instead of leaving an empty canvas.
- **Focus on a cold start (graph appearing then vanishing)** — the `graphRendered` handshake now waits for `restoreViewState`, so a queued CodeLens focus lands **after** the restored language/directory filters, heatmap and layout instead of being undone a few milliseconds later. `focusNodeById` also refuses to move the camera onto a node the force engine has not positioned yet — `cameraPosition()` with `NaN` poisons the camera for good (the scene background keeps painting while the graph becomes invisible) — and retries for up to 1.5 s instead; the blast-radius camera got the same guard. `applyViewState` is wrapped so a bad saved state can no longer abort the handshake. Finally, the deferred **initial fit-to-view** (`zoomToFit(500, 50)` 1.5 s after a graph is built) is now **cancelled** as soon as something navigates on purpose — CodeLens focus, blast radius — instead of zooming back out on top of the selection; this is why the bug only showed when Aura had never been opened (a fresh graph schedules the fit, an open panel does not).
- **Cold-start `ready` race** — the webview told the host it was ready at script-evaluation time, *before* `init()` ran (which is deferred to `DOMContentLoaded`). With a warm `.aura/graph.db` the host answered instantly with the cached graph, so a first graphData could reach a half-initialized webview: `AuraRiskMap.renderRiskDashboard()` then threw (`hooks.getGraphData` not a function), `handleGraphData` aborted before building the graph and the **loading overlay stayed on top of an empty panel** — the panel looked grey and the graph never appeared. `ready` is now sent at the end of `init()`, the satellite renders are individually guarded, and the overlay hide + `graphRendered` handshake are scheduled in a `finally` so no exception can strand them.
- **CodeLens actions on a cold start** — clicking `⟡ focus · flow · impact` before Aura had ever been opened dropped the focus and the blast radius: the command creates the panel, but the startup analysis is still running, so `openVisualizer` returned before any graph existed and the webview silently ignored the `focusNode` / `blastRadius` messages (the flowchart worked — it needs no 3D graph). The webview now posts a **`graphRendered`** handshake after its first rendered frame; the host queues **focus / follow editor / blast radius / flowchart** until that handshake and re-arms the queue whenever a new dataset rebuilds the `ForceGraph3D` instance. `blastRadiusCurrentFile` (`Aura: Blast Radius`) no longer relies on its 300 ms delay.

## [1.5.0] - 2026-10-30

### Added
- **Gamepad in pilot mode (V2 pilot tier 2)** — the free-flight camera can now be flown with a DualSense/DualShock/Xbox pad (any W3C *standard mapping* gamepad), in parallel with the keyboard and mouse. Left stick translates, right stick looks (its rate follows the **Mouse look sensitivity** setting), the analog **L2** descends and **R2** boosts proportionally to the trigger travel, **✕** resets to a full-graph overview, a touchpad click re-aims at the graph centre, **d-pad ↑/↓** step the speed multiplier, **Options** resets it and **○** leaves the flight. Sticks pass a 15 % deadzone and a 1.5 response curve, `navigator.getGamepads()` is polled inside the flight rAF loop (no motion events in the API), connect/disconnect events update the HUD immediately, and the live pad name appears in the pilot HUD. The mapping is pure and unit-tested in `flight-core` (`deadzone`, `readPadState`, `triggerValue`, `applyStickLook`, `combineInput`, `boostFactor`), keyboard and pad input are summed and re-normalized, and `auraVisualizer.gamepadEnabled` (on by default) turns polling off entirely outside pilot mode.
- **Ask Aura on architecture layers** — every Layers card in the floating palette now has the same **✨** action as communities. It sends the authoritative member list (capped, documentation excluded), the layer globs, Martin coupling (`Ca`/`Ce`/`I`), new vs baselined violations with their rule ids, and aggregated layer cycles; `@aura` is told that membership comes from `.aura/arch-rules.json` (first matching glob wins) so code fixes and rule changes stay distinct. The **Unlayered** bucket has no ask action for now.
- **`aura_get_architecture_violations` AI tool** — new shared tool for `@aura` and VS Code LM agents: evaluates the layer rules against the current graph with optional `layer`, `include_baselined` and `limit` filters, returning per-layer globs and metrics, violations and cycles. Layer globs are now part of `ArchLayerStat`, so the palette, the tool and the Architecture tab describe layers consistently.
- **Parse failure report ⚠️ (V2-17)** — a file Tree-sitter cannot parse cleanly (syntax errors) or that makes a parser throw is no longer a silent fallback: the analysis catches the failure, keeps the file's node so its imports and dependents stay visible, and records a short reason. `meta.parseFailures` carries an exact count plus a deterministic, capped sample (25 entries); the report is persisted in `.aura/graph.db` and kept up to date by incremental edits (a fixed file leaves the list, a newly broken one joins it). A **⚠ N parse failures** badge in the stats bar opens a panel listing the sampled paths and reasons — clicking a path reveals the node — and exports a Markdown report. No analysis aborts on a broken file.
- **Communities / Layers palette** — the floating palette now has a header combobox that switches between **🧩 Communities** and **🏛️ Layers** (it mirrors the heatmap selector, so either control can switch). Layer cards follow the rule order — their swatches match the graph, the legend and the Architecture tab — and clicking one dims that layer exactly like a community toggle: nodes fade, labels disappear and links touching a hidden layer dim. **All** / **None** apply to the list currently shown, an **Unlayered** card (gray, matching the Architecture tab) is added when files fall outside every layer, and a missing rules file shows an empty state with **Create / open rules file**. Selections are persisted for **both** modes with the view state (communities by stable key, layers by name).
- **Architecture rules (V2-20)** — declarative layers over the typed dependency graph in `.aura/arch-rules.json`: glob → layer assignment (first match wins), `deny` rules with `error`/`warn` severity, sibling `slices` with `shared` allowances, aggregated `no-cycles` (Tarjan SCC on the file → layer graph), source `exceptions`, and a `strict` flag for unlayered files. A pure engine (`src/arch/arch-core.ts`) is shared by the extension host, the webview bundle (`window.AuraArch`) and MCP, and reports per-layer Martin metrics (`Ca`, `Ce`, `I = Ce / (Ca + Ce)`).
- **Adoption baseline** — `.aura/arch-baseline.json` freezes existing violations (rule + source + target, deterministic ordering); only new ones alert. Create it from the Architecture tab or `Aura: Baseline Architecture Violations`; reset clears it.
- **🏛️ Architecture tab** — violations grouped by rule with severity, link types and baseline state; layer table with files/Ca/Ce/instability; aggregated layer cycles; unlayered files; Markdown export; **Create or open rules** seeded from top-level `src/` folders.
- **Structured rules editor** — the **⚙️ Edit rules** modal edits layers (name, globs, order), deny rules (source + forbidden-target chips + severity), slices (pattern + shared globs), `no-cycles`, exceptions and strict mode. Renaming a layer updates every deny reference, every change is validated by the same engine before saving, invalid forms disable **Save**, and a raw JSON fallback keeps `edgeTypes`/advanced ordering editable.
- **Structured dead-code exemption editor** — **⚙️ Settings → Dead code exemptions** now edits each custom rule as a form (reason, exact names, regex, path globs, languages, kinds), with rule ordering, add/remove, built-in defaults shown read-only, live validation through `parseDeadCodeRules`, a disabled **Save** while invalid, and a raw JSON fallback. A new **Open file** action seeds `.aura/dead-code.json`; saving still starts a re-analysis.
- **Architecture surfaces** — **Architecture layers** heatmap (layer colors, red forbidden edges, amber baselined edges), **Group by → Architecture layer** in Matrix and Chord (red DSM cells with ✖), a sortable **Layer** table column, a detail-panel section with every outgoing violation, and a status-bar item showing the active file's layer or violation count with the offending imports in the tooltip.

### Fixed
- Selecting a file from an **Architecture layer row** before ever clicking a node now applies the configured selected-node effect. The bloom composer is built after the graph becomes visible (with a short retry), and the selective bloom mesh is restricted to `BLOOM_LAYER` so it is no longer drawn as an opaque pale-blue sphere in the main pass.
- **Parse-failure false positives** — valid modern syntax the bundled Tree-sitter grammars predate no longer shows up in the report: TypeScript import type expressions (`import('./x').Type`, with their cascading MISSING/stray-brace fallout), CSS comma-separated keyframe selectors (`0%, 100%`) and `url(#fragment)` values are recognised as grammar gaps and ignored, while real errors (unexpected tokens, missing structural braces) still alert. Scanning Aura itself now reports zero parse failures.
- **Restored spread applies at startup** — the saved **Spread** value was written to the charge/link forces after the layout had already cooled, and cooling down is what makes force changes invisible (alpha is the temperature). On launch the graph therefore stayed compact at the centre until the slider was nudged, which called `d3ReheatSimulation()`. Restoring a different spread now restores the engine budget and reheats with a bounded settle, so the saved repulsion shapes the very first layout (a second restore with the same value does not reheat).
- **Filters no longer nudge the settled layout** — changing the **Edge confidence** selector, clicking **All** in the file explorer when every folder is already visible, or any other visibility change that leaves the visible set untouched no longer re-feeds the dataset. Every `graphData()` feed reheats the force engine (synchronous warmup + live cooldown), which drifted every node and was perceived as a small clockwise rotation of the whole graph. Genuine filter changes are still fed, but with zeroed warmup/cooldown so the remaining nodes keep their positions.
- **Architecture edits keep the 3D view** — saving a rule, or creating/clearing the baseline, used to re-send the whole graph: the `ForceGraph3D` instance was rebuilt, the force layout restarted and the camera snapped back to its default centered framing. The host now sends an annotation-only `archUpdate` message (layers, violation counters, red edges) that the webview patches in place, so camera position and the settled node layout are preserved.

### Removed
- **Legacy in-panel AI chat** — the hidden **✨ Aura Assistant** side panel and its dead plumbing are gone (`src/chat.ts`, `webview/js/chat.js`, the `chat-toggle`/`chat-panel` markup, the `chatRequest`/`chatChunk`/`chatDone`/`chatError`/`chatTool` messages and the `body.chat-open` CSS). - **Symbol cycles (V2-03)** — direct recursion (`walk() → walk()`) and mutual recursion (`parse() → validate() → parse()`) are detected from resolved call sites with the call line of every step. Cycles are stored in `symbol_cycles` / `symbol_cycle_steps`, shown in the detail panel's **🔄 Symbol cycles** section and the **Risk** dashboard, flagged **🔁 recursive / mutual recursion** in the flowchart badge, recomputed after incremental edits, and returned as `symbol_cycles` by the MCP `find_cycles` tool. Ambiguous same-name targets are marked with confidence 0.5.
- **Edge confidence (V2-08)** — every resolved edge now carries a 0–1 confidence score: 1.0 exact/relative/alias, 0.9 extension/index, 0.8 vendored suffix, 0.6 basename, 0.5 ambiguous; function-call edges use 0.8 (unique) / 0.5 (ambiguous) and inheritance 0.9. - **Import alias resolution (V2-12)** — imports now resolve through `tsconfig.json`/`jsconfig.json` (`baseUrl` + `paths`, simple relative `extends`), static Vite/webpack `resolve.alias`, and Python `src/` layouts. `@/components`, `~/lib`, `@app/*` and dotted Python imports produce real edges instead of false orphans; relative/extension/index/suffix/basename fallbacks are preserved.
